# AI engineer review (0.7.1-rc2 code)

> **Resolution status (0.7.3-rc4):** the top findings were fixed or documented: verdict logic, normaliser/scam rules, firewall regexes and provenance, approval payload visibility, debug-key fencing, feed sequence floor, doc corrections. Everything else raised below is still open unless CHANGELOG.md 0.7.3-rc4 says otherwise; the open items are listed in KNOWN_LIMITATIONS.md. The text below is the original review of the 0.7.1-rc2 code and is not rewritten.

Produced by a separate AI reviewer instance briefed as a senior applied-NLP / on-device ML / LLM-agent-safety engineer. It re-ran the project's trainer (the shipped model reproduces byte-for-byte), wrote its own 54 benign and 41 scam test messages, and ran ablations. All numbers come from small, single-author, partly parallel, synthetic data (the reviewer's own set included); they describe this narrow domain, not real traffic. Not yet acted on unless stated in CHANGELOG.

**Verdict:** careful engineering (deterministic, bounded, hardened loader, raise-only model, candid docs) but thin evidence. By default the product is the regex rules, which catch almost nothing of unseen scam wording; the optional model is a modest ranker with an arbitrary operating point, easy to evade, with misleading "explanations". The agent firewall is a sensible fail-closed skeleton whose security value hangs on self-reported provenance and narrow detectors.

| # | Sev | Finding |
|---|---|---|
| F1 | High | **Default detection is nearly nil and undocumented.** Rules-only recall: train 10/66, test 4/25, reviewer's unseen set 2/41 (4.9%), 0 false positives on 54 benign. Hybrid (model on): test 11/25 (1 FP), unseen 23/41 (3 FP). Docs quote only the model's 9/25. The textbook example "Your account has been suspended. Verify your identity immediately..." gets CLEAR / "No known warning signs" while its "Why" lists urgency and threat language (contradiction). |
| F2 | High | **Evaluation cannot support rate claims.** 96% of train items have their translation in train; the test set is ~13 independent scam units, not 25. Random 5-fold CV leaks translation pairs: OOF recall 0.456 vs 0.330 with pair-grouped CV (AUC 0.897 vs 0.851). Threshold rule ("OOF FPR <= 2%" on 70 benign) is set by the 2nd-highest benign score; 0.825 sits between two test-benign scores (0.823, 0.831) - at 0.823 test FP is 2/25, at 0.84 it is 0/25. Intervals: recall 9/25 -> Wilson [20.2%, 55.5%]; FP 1/25 -> [0.7%, 19.5%]. No sign of lexical near-duplicate leakage (median nearest-neighbour cosine 0.34), but thematic overlap is complete. Needs >= 300 benign with 0 FP to claim <1% FP. |
| F3 | Med-High | **Model quality/calibration.** Seeds don't matter (30 seeds: recall 0.36 every run); hyper-parameters do: stronger L2 raises AUC (0.89 -> 0.96) but compresses scores so the fixed 0.825 threshold gives 8% recall. 2^10 buckets matches 2^16. Overfit (53/136 train scores >0.99 or <0.01), not a posterior probability (PPV 0.91 at 50% prevalence, 0.53 at 10%, 0.09 at 1%). Learning curve still steep (adding the reviewer's 95 messages lifts test AUC 0.883 -> 0.946): data-limited. FP on reviewer's benign: 3/54 (5.6%, Wilson [1.9%, 15.1%]) - two were legitimate bank fraud alerts. Recall on unseen scams 23/41 (56%, Wilson [41%, 70%]). |
| F4 | Medium | **Windowed scoring does not fix padding.** Of 32 flagged scams, a 10-word suffix leaves 9 flagged; prefix padding is erratic (9-31 of 32); both-sides 3-6 of 32. Documented "5 of 9" depends on the filler. Window-max inflates false positives on long benign text (5.1% for 1 message -> 32.6% for 10 concatenated). Typos: letter swaps leave 15/32 flagged. |
| F5 | Medium | **Normaliser/rules gaps.** Homoglyph map covers lowercase only, folded before lowercasing (uppercase Cyrillic capitals evade the model 0/32). ScamAnalyzer rules do not use the normaliser at all (zero-width, homoglyph, leetspeak, spacing each drop "Please share your password now" to CLEAR). Leetspeak fold garbles `$1000`, `10pm`, `4G`. Messages <5 tokens are ignored ("Send bitcoin now" scores 0.93; URL-only messages ignored). Misses: formal "kindly revert with your online banking credentials" (0.26); posten lookalike in a subdomain. No prompt-injection path against the app itself (no LLM; text is arithmetic). |
| F6 | Medium | **Explanations mislead.** 61 of 96 displayed terms contain a stopword; character trigrams carry ~4.3 of the logit but cannot be shown (words 0.75, bigrams 0.32). "Explainable" overstates. |
| F7 | High | **Agent firewall: provenance self-reported; "only tightens" is false.** Same request: ASK as EXTERNAL_CONTENT, ALLOW as USER_DIRECT; `USER_DIRECT` + base64 AWS key or private conversation text -> ALLOW. Works only if the harness computes provenance by taint tracking, not the LLM. |
| F8 | High | **Approval UI can hide what is approved.** Payload "not shown": an EXECUTE_COMMAND with summary "Run the unit tests" and a destructive payload shows only the agent's summary ("lies in the loop"); approval fatigue (every user-driven high-risk action asks). |
| F9 | Med-High | **Firewall detectors: low recall, high noise.** Secrets: 10/25 formats detected (missed: PGP block, AWS secret assignment, Stripe `sk_live_`, Google `AIza`, DB URLs, `DB_PASSWORD=`, quoted JSON password, `client_secret=`, seed phrases, WIF, Azure keys, Basic auth). PII checks 6/6 (Luhn, IBAN, fnr solid). Destination URL and summary are not scanned. Injection indicators catch 13/38 attack phrasings (misses other languages, encodings, "forget everything", markdown-image exfil, Unicode tag characters). False positives on 40 adversarial-benign texts: secrets/PII 6/40; injection 22/40 ("Please send the files to Anna", "Pay 500 kr to ...", "You are now connected to the VPN", `curl ...`); ZWJ/ZWNJ/RLM text trips hidden-text rule; random 13-digit numbers flagged as cards ~10% of the time. |
| F10 | Medium | **Dead code / over-broad grants.** `trustDestination` never called; pairing grants all actions; suffix trust would trust `evil.example.com` via `example.com` and `attacker.github.io` via `github.io`; trusted host + EXTERNAL_CONTENT + benign payload = ALLOW. |
| F11 | Low-Med | **Hybrid design.** Raise-only is the right safety property. But model is the main detector and is OFF by default; SECRET_REQUEST fires on "Never share your password" (no negation handling; 3/70 benign train messages); `ML_AGREES` implies corroboration though rules and model share stereotypes; ML-only flag shows the same headline as a rule hit; Norwegian text appends English sentence. |
| F12 | Medium (High before any download path) | **Model supply chain/governance.** In-file SHA-256 detects corruption only (a crafted model with a valid checksum loads; in the APK the APK signature covers it); threshold only needs to lie in (0,1); no version monotonicity, no data hash/metrics/licence in the file. Strength: reproducible training. `MessageAi.analyze` 138 us/message on host (docs' 40-50 us is classifier only); ScamAnalyzer recompiles regexes per call; no on-device latency/battery data. Corpus provenance statement inconsistent (developer-written vs AI-assisted). Tech evaluation (LiteRT/ML Kit/Gemini Nano) directionally right but omits MediaPipe Text Classifier, ONNX Runtime Mobile, ML Kit GenAI (reviewer's recollection, unverified). |
| F13 | Info | **OWASP LLM mapping** (from memory): partly addresses LLM01 (heuristic), LLM02, LLM06 (main target), audit; not LLM03/04/05/07/08/09, memory poisoning, plugins, multi-step. Structural limit: policy decision point without an enforcement point; a capability-broker design would have real teeth. |
| F14 | - | **Honesty list** (16 items): 9/25 quoted without rules/hybrid numbers; CV row optimistic; "explainable"; "homoglyph invariance" holds for the model only; "5 of 9 escape"; "provenance only ever tightens"; "per-agent permitted action set" not implemented; test count 4,522 vs 4,533; SOURCE_PROVENANCE says no model weights bundled; AI-vs-developer authorship inconsistent; stale KNOWN_LIMITATIONS first bullet; README version; store text "flags pressure..."; UI calls a 66 KB n-gram logistic regression a "language model"; ML-only flags worded like rule hits; CLEAR shown with a Why list. |

**Roadmap (2 weeks):** report rules-only / model-only / hybrid metrics with intervals; remove CLEAR-with-reasons; rename "language model" to "text classifier"; run rules through the normaliser and fix uppercase homoglyph folding; short-message-plus-link rule; negation handling; group-aware CV and "recall at <= X% FP" operating point with calibration, 2^12 buckets, stronger L2; drop or rewrite the term list; firewall: show the real command/payload head, require taint-tracked provenance, ASK for untrusted outbound regardless of provenance, scan destination and summary, add secret formats, gate injection indicators on external text only, per-agent action grants.
**Roadmap (2 months):** real, consented, redacted data (>= 1,000 scams, >= 3,000 ordinary incl. hard negatives); two annotators + kappa; frozen group-aware test set + red-team set; release gate such as recall >= 70% at <= 1% FP; prototype a small multilingual encoder (int8) against the baseline; model card and signed model manifest with rollback floor; local-only drift signals; reference SDK with taint tracking and an MCP gateway proxy as an enforcement point.

**Done well:** pure/deterministic/bounded classifier; hardened model loader (400-case bit-flip test); reproducible training; self-critical docs and OFF-by-default experimental model; abstention on tiny inputs and robustness to emoji/punctuation/mixed language; fail-closed firewall foundations (hash-bound single-use approvals, bounded log, UID+certificate pinning, URI-parsed hosts, correct Norwegian PII checks, bounded scan times except the two ReDoS cases found by the security review).
