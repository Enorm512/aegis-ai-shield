# Cybersecurity expert review (0.7.1-rc2 code)

> **Resolution status (0.7.3-rc4):** the top findings were fixed or documented: verdict logic, normaliser/scam rules, firewall regexes and provenance, approval payload visibility, debug-key fencing, feed sequence floor, doc corrections. Everything else raised below is still open unless CHANGELOG.md 0.7.3-rc4 says otherwise; the open items are listed in KNOWN_LIMITATIONS.md. The text below is the original review of the 0.7.1-rc2 code and is not rewritten.

Produced by a separate AI reviewer instance briefed as a senior mobile/network security expert, read-only, with permission to run experiments in a scratch folder. Not a human audit. "Confirmed" = it ran code; "unconfirmed" = reading only / needs a device. Nothing here has been fixed yet unless stated in CHANGELOG.

**Verdict:** the plumbing is sound (signature before parse, pure-Java engine, DNS-only tunnel with two /32 routes, no WebView/exec/dynamic loading, candid docs). What fails is the layer above it: detection verdicts are easy to evade or self-contradictory, feed key management cannot recover from a mistake or compromise, and the agent firewall depends on a self-reported label.

| # | Sev | Status | Finding |
|---|---|---|---|
| 1 | High | confirmed | Obviously bad inputs get level CLEAR ("No known warning signs"): APK capability combos scoring <3 (accessibility+overlay+boot = 2.75; SMS+overlay+internet; install-packages dropper) carry the banker/SMS-exfil findings yet show CLEAR; brand-plus-keyword hosts (`dnb-login.com`, `apple-id-locked.com`, `netflix-billing.com`, `dnb.evil.com`, `secure.nordea.verify-id.com`) score CLEAR (UrlAnalyzer knows 4 brands; LookalikeDetector only whole-label/one-edit); message rules run on raw text so one zero-width space or Cyrillic "а" evades them; bare-domain links in messages (`dnb-login.com/verify`, `bit.ly/3xyz`) are never analysed; urgency+threat alone scores 0. Store text over-promises "hidden redirects". |
| 2 | High (design) | confirmed | Feed key management unrecoverable: the sequence floor is global, so one bundle (compromised key or operator typo, up to 15 digits) with sequence 999999999999999 permanently rejects every later bundle from a rotated key (only app-data wipe recovers). No expiry cap, no per-bundle delta limit, only 8 protected names (a signed `google.com` entry blocks most of the phone), no revocation/threshold signing/key expiry. |
| 3 | High (design) | confirmed | Agent firewall allows by default when the agent claims `USER_DIRECT` (outbound to an arbitrary host, `READ_SENSITIVE` -> ALLOW); lying loosens policy, contradicting the docs ("fail-closed", "only tightens"). SensitiveData misses common secret formats (`DB_PASSWORD=`, `{"password":"x"}`, `AWS_SECRET_ACCESS_KEY=`, `client_secret=`, Basic auth, dotted card numbers). Approver cannot see the payload. Pairing grants all actions; `trustDestination` is never called (dead branches); audit log is in memory and flushable. |
| 4 | Med-High | confirmed | ReDoS on the single gateway thread: `(?m)^\s*(?:system|...)\s*:` took 48.6 s on 50k newlines; JWT alternative `eyJ-`x25,000 took 13.5 s (scanned twice). One slow request blocks every agent and the pairing prompt. |
| 5 | Medium | confirmed | Debug test key fenced by convention only: forged bundle signed with the committed private key accepted by the debug APK; debug and release share `applicationId`; debug build shows a normal import button with no warning; the release gate (`check_release_apk.py`) is manual, not in CI, and counts total keys (will be weakened when a real key ships). |
| 6 | Medium | - | Doc/UI overclaims and drift: SECURITY_REQUIREMENTS says no INTERNET permission; ARCHITECTURE and top of KNOWN_LIMITATIONS are stale (no VPN, uncompiled); version drift across README/RELEASE_CHECKLIST/BUILD_INSTRUCTIONS; CI installs android-35 but build needs 36; stale `reports/RELEASE_SHA256SUMS.txt`; "DNS goes to your network resolver as without Aegis" is false for Private DNS Automatic; stopping the VPN called "fail closed" (it is fail-open for filtering); SECURITY_AUDIT claims no defect in rollback logic although #2/#11 are rollback/rotation gaps; protected-names list is only 8 names. |
| 7 | Medium | unconfirmed | Gateway caller identification may fail on API 30+ (no `<queries>`); pairing is trust-on-first-use of a package name only (typosquat risk); UI race: a new pairing request can replace the approval dialog under the user's finger ("Approve once" position becomes "Allow" pairing); permanent refusal after signing-certificate rotation. |
| 8 | Medium | confirmed | Any local app can starve DNS: 8 workers + 64 queue, no per-source fairness; 100 slow queries -> 28 dropped. Any app can probe the block list via NXDOMAIN. |
| 9 | Medium | unconfirmed | DNS privacy/efficacy: Private DNS "Automatic" is silently downgraded to plaintext; strict Private DNS likely bypasses Aegis; sockets are protected but not bound to the chosen network; always-on + "block connections without VPN" would black out the device. |
| 10 | Med-Low | confirmed | No TCP DNS service: truncated answers lead clients to retry over TCP to the virtual address, which is dropped -> large answers (DNSSEC, many records) time out while the VPN is on. |
| 11 | Low | confirmed | Floor not enforced when reloading stored bundles (older bundle file accepted if written to disk; clearing app data resets floor). Needs root/file-write. |
| 12 | Low-Med | - | Supply chain: `verify-signatures=false` (checksums are trust-on-first-use), wrapper jar unverified, CI actions pinned to tags not SHAs, no CVE scan; `ThreatBundleTool keygen` writes an unencrypted private key; `TrustAnchors.add` checks only a 256-bit group order; Conscrypt/BoringSSL verification untested. |
| 13 | Low | confirmed | URL parser differential: `IDN.toASCII` is IDNA2003 (`faß.de` -> `fass.de`), browsers use IDNA2008/UTS46 -> analysed host can differ from visited host. |
| 14 | Low | unconfirmed | Pre-auth Binder parcel deserialisation (platform); no `filterTouchesWhenObscured`/`FLAG_SECURE` on approval UI; `startProtection` early return without `startForeground` on repeated start; `ThreatStore` IOException uncaught in VPN start; AXML name fallback differs from Android's TypedArray (false positives only). |

**No defect found** in: 180,000 mutated manifests, 100,000 mutated bundles, 300,000 random packets (0 unexpected exceptions); ApkArchiveInspector (no extraction, overlap/ratio checks sound); temp-file and share-intent handling; backup/cleartext/PendingIntent settings; approval hash framing; signature-before-parse and canonical base64; release APK trust anchors (0).

**Genuinely well done:** honest docs, bounded fuzzed pure-Java core, tight DNS-only tunnel, permission pinning, atomic store with fallback, the earlier 15 fixes held.

**Top 5 before any release:** (1) fix verdict logic and store copy; (2) redesign feed trust (per-key sequence/epoch, caps, top-domain guard, expiry, revocation, rehearsed rotation); (3) harden the agent firewall (bounded regexes, scans off the gateway thread with a wall-clock fail-closed limit, show the payload, race-proof pairing UI, prove caller identification on API 30+); (4) fence the debug key (`.debug` applicationId suffix, visible banner, CI gate keyed on the debug key id, no debug APK in release distributions); (5) run the device plan, bind upstream sockets to the chosen network, add fairness/TCP/Private-DNS handling, independent human review, CVE scan, SHA-pinned CI, corrected docs.
